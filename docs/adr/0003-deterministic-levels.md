# 0003 关卡按关卡号确定地生成

- 状态：已采纳
- 日期：2026-10-02

## 背景

- 关卡制解谜游戏需要大量关卡，一个人没法一关一关手工设计。
- 游戏没有失败状态，卡住时只能靠提示或跳关，所以每一关都必须有解。
- 在抖音上，"99% 的人过不了第 N 关"是常见的传播方式。同一关所有玩家看到的必须一样，录屏、分享和攻略才对得上。

## 决定

1. 关卡由程序生成。关卡号决定随机种子，种子决定整关的内容。
2. 生成方法：先把箱子随机地正好铺满，这就是答案；再把物品打乱，放进托盘。这样每关都保证有解，提示也可以直接按这个答案给。
3. 难度只由参数决定：箱子尺寸、物品形状的复杂度、拉杆槽（不能放东西的格子）的数量。前几关的参数可以手工指定，用来做教学。
4. 生成器是 core 里的纯函数：输入关卡号，输出关卡数据。

## 确定性的约束

"同一关号结果一致"指的是在所有设备上都一致，不只是在同一台机器上一致。同一个小游戏在 iOS 和安卓上跑在不同的 JavaScript 引擎里（iOS 是 JavaScriptCore，安卓一般是 V8），所以生成代码要遵守：

- **随机数**只用 core 自带的种子随机数，不用 `Math.random`。
- **不读时间。** 回溯搜索的预算按步数算，不按耗时算，否则慢手机上会生成出不一样的关卡。
- **只用结果确定的运算。** 加减乘除、`Math.floor`、`Math.imul`、位运算在所有引擎上结果都一样。`Math.pow`、`Math.exp`、`Math.log`、`Math.sin` 这类函数，JavaScript 规范允许各引擎给出近似结果，最后一位不同就可能让后面的选择走向不同的分支，所以不用。drafts 里的 `weightedOrder` 用了 `Math.pow`，1.1 迁移时要换掉。
- **排序的比较函数**对同样的输入必须给出同样的结果，不能在比较函数里取随机数。
- **测试里固定前若干关的生成结果指纹。** 生成器的任何改动都会让指纹变化、测试失败，保证每次改动都是有意的。

## 理由

- 程序生成解决了关卡数量问题；先铺满再打乱，又保证了每关有解。
- 关卡号即种子，不需要服务器下发关卡，也不需要把几百关的数据打进包里。

## 代价

- 不能逐关手工打磨，难度曲线只能靠参数调。以后需要精调时，可以把生成结果"烘焙"成数据再手工改（阶段 5，到时写新的 ADR）。
- 改生成器就等于改所有关卡。上线后再改生成器，玩家看到的关卡会变样。如果存档里保存了进行中的关卡，要同时记录生成器版本，版本对不上就让这一关重新开始。
- 生成要足够快。单测里限制每关不超过 50ms。

## 什么时候重新考虑

- 需要逐关手工调整难度。
- 生成速度或关卡质量达不到要求。
