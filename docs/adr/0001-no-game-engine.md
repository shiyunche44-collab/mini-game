# 0001 不用游戏引擎：TypeScript + 原生 Canvas 2D

- 状态：已采纳
- 日期：2026-10-02

## 背景

要做的是一款关卡制的休闲解谜小游戏"整理行李箱"：箱子是网格，把物品拖进去，点一下旋转，全部装下就过关。同时上微信和抖音，靠广告变现。

开发方式：代码主要由 AI 在云端编写，并跑自动化测试。用户会写代码，自己用微信和抖音开发者工具做真机验证。美术先用 emoji 和色块。

## 考虑过的方案

| 方案 | 好处 | 问题 |
|---|---|---|
| Cocos Creator | 国内小游戏最常用的引擎；有可视化编辑器；能直接打出微信和抖音的包；资料多；以后方便找美术和其他开发者协作 | 场景要在编辑器里搭，云端操作不了编辑器，需要用户在本地配合；代码包更大 |
| Laya、Phaser 等 2D 引擎 | 比 Cocos 轻 | 两个平台的能力照样要自己适配；玩法用不到它们的大部分功能 |
| TypeScript + 原生 Canvas 2D | 代码包能控制在 300KB 以内，启动快；全部是代码，云端能完成开发和自动化测试，每个版本都能发手机试玩链接 | 没有可视化编辑器 |

## 决定

不用游戏引擎。全部代码用 TypeScript 写，画面用 Canvas 2D 自己画，esbuild 把每个平台的入口打成一个文件。运行时不依赖任何第三方库。

## 理由

- 玩法只需要网格、拖动、旋转和简单的补间动画，用不到物理、骨骼动画、粒子和场景编辑器。
- 包小，启动快。
- 一切都是代码。游戏层可以在 node 里用假平台完整测试，也可以在浏览器里用 Playwright 跑冒烟测试，不需要有人打开编辑器。
- 广告、分享、录屏、侧边栏这些平台能力，用引擎也要自己封装，引擎在这部分省下的工作有限。

## 代价

- 界面和动效都靠写代码，调视觉要改代码、看截图。
- 主循环、补间、输入识别、绘制工具要自己写，这就是 engine 层。
- 以后找美术或其他开发者协作，对方要读代码，没有编辑器可用。
- 换图、图集、音效这些引擎自带的能力要自己做（阶段 5）。

## 什么时候重新考虑

- 玩法要加物理、粒子、骨骼动画这类复杂表现。
- engine 层开始自己实现场景树、动画系统这类引擎级的东西。
- 需要美术或策划直接在编辑器里调界面和关卡。
