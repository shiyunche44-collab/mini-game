# 路线图

分阶段的任务和进度。下一个任务就是表里第一个没打 ✅ 的任务。工作方式见 [CLAUDE.md](../CLAUDE.md#工作方式)。

每做完一个任务，在同一次提交里把它标成 ✅。阶段结束后由用户决定是否合并到 `main`。

## 阶段 1：核心逻辑（只有逻辑，没有画面）

| 编号 | 任务 | 验收标准 | 状态 |
|---|---|---|---|
| 1.1 | `rng`、`items` 迁移成 TS + 单测（旋转去重、emoji 位置） | `npm run check` 通过 | ✅ |
| 1.2 | 关卡生成器 + 单测：前 200 关都正好铺满；同一关号结果一致；每关生成小于 50ms | 同上 | ✅ |
| 1.3 | `npm run levels:preview`：在命令行打印前 N 关的文字版网格和物品清单 | 用户看前 10 关，判断难度梯度是否合理 | ✅ |
| 1.4 | 一局规则 `game.ts` + 单测：放置、移除、旋转、提示、快照与恢复 | `npm run check` 通过 | ✅ |
| 1.5 | 存档模型 `progress.ts` + 单测：读写、版本迁移、插屏频控；删除 `drafts/` | 同上 | ✅ |

备注：

- 1.1：草稿里的 `weightedOrder` 用了 `Math.pow`，已按 ADR 0003 换成逐个按权重抽取的写法（分布相同）。`test/core-determinism.test.ts` 检查 core 里没有 `Math.pow`、`**`、`Math.random`、`Date` 这类写法。
- 1.2：已按 ADR 0003 加上前 200 关的指纹测试。生成器改动让某一关变样时，要同时加 `GENERATOR_VERSION`、更新指纹。单次搜索的步数预算从草稿的 4000 降到 300：草稿的最坏一关要 40～60ms，现在 2 万关里最慢约 17ms，每次尝试成功率在 80% 以上。
- 1.4：`Level` 新增 `rotate`（这关能不能旋转），一局的规则要用；不影响生成结果，指纹没变。提示按答案摆：已经摆对的不挪，形状相同的物品互换，先摆大件，用托盘里的物品，挡路的退回托盘；不能旋转的关卡里只用朝向本来就对的物品。`restore` 对存档逐项检查，要么整份恢复，要么不改动。"重来"保留朝向和提示次数。
- 1.5：存档里记下进行中的关卡是哪个 `GENERATOR_VERSION` 生成的，对不上就让这一关重新开始（ADR 0003）。
- 1.5 做完的样子：`Progress` 是纯数据（版本、当前关卡、进行中的局面、上次插屏时间），`loadProgress` 对 storage 里读出来的任何东西都不抛错，能留的进度尽量留（损坏就从第 1 关开始；局面不对只丢这一局；版本比现在新就只留关卡号）。读写 `platform.storage` 由 game 层做，key 是 `SAVE_KEY`。core 里没有时钟，插屏频控的函数由调用方传 `now`。插屏规则：通关第 5、8、11…… 关后弹，离上次不足 90 秒不弹（这个 90 秒是我定的，没有别处依据，可以改 `INTERSTITIAL_MIN_GAP_MS`）。`drafts/` 已删除。

## 阶段 2：运行时 + 静态画面（Web）

| 编号 | 任务 | 验收标准 | 状态 |
|---|---|---|---|
| 2.1 | engine：主循环、补间、输入识别（点击 / 拖动）+ 单测 | `npm run check` 通过 | ✅ |
| 2.2 | Web 平台实现、Web 入口、`build:web` 和 `dev` 命令、包体检查；先只画背景 | 浏览器能打开，看到背景 | ✅ |
| 2.3 | 布局 + 静态绘制：箱子、托盘里的物品、按钮、行李牌 | 375×667、390×844、桌面三种尺寸的截图发给用户确认视觉 | ✅ |

备注：

- 2.1：已按 [ADR 0004](adr/0004-platform-frame-and-clock.md) 给 Platform 加了 `requestFrame`（帧时间，单调）和 `now`（墙上时钟，要存档的时间用它），假平台用 `advance(ms)` 手动推进时间。三个平台实现（2.2、4.1）要补上这两个成员。点击 / 拖动的阈值（`TAP_MAX_MOVE_PX` = 10 像素、`TAP_MAX_MS` = 500 毫秒）是我定的，没有别处依据，真机试玩后可以改。主循环把 dt 夹在 100ms 以内。`draw.ts`（圆角矩形等）留到 2.3。
- 2.2：入口的类型库已按这个办法解决：每个入口 `X.ts` 配一份 `src/entry/tsconfig.X.json`，`tools/typecheck.mjs` 逐个检查，入口没配 tsconfig 会失败。web 入口带 DOM；4.1 给微信、抖音入口配各自的类型库。
  - Web 平台没有 `onResize`：窗口大小在创建时读一次，改窗口大小要刷新页面（记在 backlog）。广告只在控制台打日志并当作看完，弹层版本在 3.4。
  - 画面现在只有一层渐变背景（`game/start.ts`、`theme.ts`）。包体检查已并入 `npm run check`，现在 web 产物约 3KB。
- 2.3：静态画面由 `game/PlayScene.ts` 画，位置全部来自纯函数 `game/layout.ts`（`computeLayout`），单测在 5 种屏幕上扫前 60 关，检查元素不越界、不重叠、托盘里每件物品都有位置。箱子的格子从大到小试，第一个让托盘也放得舒服的就用；托盘里每件物品占一个正方形位置（边长是它最长的一边），旋转时别的物品不会换位置。画物品在 `game/pieceView.ts`，以后换图只改这个文件。圆角矩形在 `engine/draw.ts`，用 `arcTo` 画。
- 2.3 调试用：Web 页面支持网址参数 `?level=10&hints=5`，直接看第 10 关并先摆好 5 件（由真实的 `Game.hint()` 摆）。只有 Web 入口认；3.3 起指定关卡不读也不写存档。
- 2.3 画面上的几个选择是我定的，截图确认时可以改：配色（见 `game/theme.ts`）、提示和跳关按钮右上角的"广告"角标、拉杆槽用深灰色加一条槽、行李牌的样式。

## 阶段 3：可玩原型（Web）

| 编号 | 任务 | 验收标准 | 状态 |
|---|---|---|---|
| 3.1 | 拖动放置：吸附预览、放不下退回托盘、手指拖动时物品抬高 | 假平台测试：把一件物品拖进箱子 | ✅ |
| 3.2 | 点按旋转（托盘里和箱子里都能转）+ 动画 | 假平台测试 | ✅ |
| 3.3 | 过关：合盖、盖章、登机牌、下一站、存档 | 假平台测试：自动通关第 1 关 | ✅ |
| 3.4 | 提示、跳关、重来 + 模拟激励视频 | 假平台测试：看完广告才给提示，提前关闭不给 | ✅ |
| 3.5 | Playwright 冒烟测试 + 发布手机试玩链接 | **玩法门禁**：用户试玩前 10 关。好玩再进入阶段 4，不好玩先调玩法 ✅ |

备注：

- 3.1：拖动的逻辑都在 `game/PlayScene.ts`，吸附的计算是纯函数 `game/snap.ts`。规则：手指按在物品上（托盘里按物品的正方形位置，箱子里按格子）拖动，物品放大到箱子里的大小、抬高；拖到放得下的位置时画半透明预览；松手落进去，放不下就飞回去。从箱子里拿起的，松手在托盘上是退回托盘，其他放不下的情况回到原来的位置。拖动期间 `Game` 的状态不动，松手才改，所以被系统打断什么都不会丢。
- 3.1：物品比手指高出 0.7 格（`LIFT_CELLS`），吸附半径 0.8 格（`SNAP_RADIUS`），放大 / 落位 / 退回的时长是 110 / 130 / 240 毫秒。这些数字都是我定的，没有别处依据，3.5 试玩时看手感再调。吸附按"拿起完成之后的大小和高度"算，不按动画中间的值，所以手很快时结果也一样。
- 3.1：假平台修了一个浮点问题：时间不对齐帧点时，`advance(FRAME_MS)` 可能漏掉一帧。`FakeCanvas2D` 的调用记录里也加了 `shadowBlur`，用来测拿起时的影子。
- 3.2：点中物品（托盘里按它的正方形位置，箱子里按格子）调 `Game.rotate`。转得动：把转好之后的物品倒转 90° 画出来再转回 0，约 190ms，末尾略过冲；连点时接着当前角度继续转。箱子里周围没空位转不开：物品左右抖一下（约 300ms，幅度 0.12 格，越抖越小）。这一关不能旋转、或者物品怎么转形状都一样（2×2 的书、单格的袜子）时点了没有任何反馈。这几个数字和"不能转的不给反馈"都是我定的，3.5 试玩时看是否需要提示玩家。
- 3.2：抖动的波形在 `engine/tween.ts` 的 `wave`，用折线代替 sin。测试辅助抽到了 `test/play-helpers.ts`，3.1、3.2 的测试共用。
- 3.3：流程在 `game/Session.ts`：读存档、玩当前这一关、过关、下一站，并把触摸交给当前场景或过关画面。`PlayScene` 只发"局面变了"和"全部装下了"两个事件，不碰存档和广告。存档：每次摆放、取出、旋转之后存进行中的局面；全部装下的那一刻就存"下一关"，不等玩家点"下一站"，所以在登机牌上退出也不会白玩（代价是这一次的插屏广告会跳过）。存档损坏、版本不对、局面对不上都不会崩，规则见 `core/progress.ts`。
- 3.3：过关画面在 `game/WinOverlay.ts`：先等最后一件物品落稳（220ms），箱盖从上面合下来（420ms），印章压下去（260ms），最后暗幕加登机牌升起（420ms），共约 1.6 秒。登机牌出来之前点一下屏幕直接跳到最后，不会进下一关；出来之后点"下一站"才进。登机牌上写：出发地（这一关）、到达地（下一关）、行李件数、提示次数、登机口（由关卡号算出的装饰）和条形码（同样由关卡号算，不用随机数）。
- 3.3：点"下一站"时按 `shouldShowInterstitial` 判断弹不弹插屏（通关第 5、8、11…… 关，且离上次不足 90 秒不弹），放完才进下一关，记下的是放完的时间；广告期间不响应触摸。重来、提示、跳关三个按钮现在还是摆设，3.4 做。
- 3.3：调试参数 `?level=N` 现在不读也不写存档（进度只在这次打开里有效）；`&hints=99` 把箱子摆满，直接进入过关画面，用来看结算。
- 3.3：下一关直接切换，没有转场动画。这是我没做的，记在 backlog。
- 3.4：按钮的逻辑在 `game/Session.ts`，`PlayScene` 只发"点了哪个按钮"的事件，并提供 `restart()` 和 `applyHint()` 两个动作。重来免费：箱子里的物品飞回托盘，朝向和提示次数保留，箱子本来就是空的就不存档。提示和跳关先 `rewarded(...)`，返回 true 才给；返回 false（中途关闭、加载失败）什么都不给，也不存档。看广告期间 `busy`：不响应任何触摸，重复点按钮只请求一次广告。跳关后不弹插屏（设计文档规定），也不出现过关画面。提示摆好的物品从原位飞到答案位置（220ms），被挤开的飞回托盘；提示先摆最大的（规则在 `Game.hint`）。
- 3.4：Web 的模拟激励视频是 DOM 弹层（`platform/web.ts`）：暗幕加卡片，倒计时 3 秒（`MOCK_AD_SECONDS`，我定的，真广告通常 15～30 秒）后才能点"领取奖励"，右上角 ✕ 随时可以关（返回 false）。同一时间只有一个广告，已经有一个在播时再请求直接返回 false。弹层是 DOM，node 里测不了，3.4 用 Playwright 手动验证了一遍（提前关闭、等倒计时领取、重来、跳关、存档），3.5 会把它做成自动的冒烟测试。插屏广告 Web 上还是只打日志。
- 4.2 提醒：微信、抖音没有 DOM，Web 这个弹层不能直接用。"没填广告位 id 时退回模拟广告"可以用 `wx.showModal` / `tt.showModal` 做一个同样规则（看完才给、可以提前关）的确认框，到时候再定。
- 3.5 已就绪的部分：`npm run smoke`（`tools/smoke.mjs`）在 Chromium 里把 Web 版玩一遍：页面能打开、手机触摸和鼠标拖动、刷新后接着玩、提示和跳关的模拟广告（提前关闭不给）、通关第 1 关出现登机牌、转屏刷新。它需要浏览器，所以不在 `npm run check` 里，CI 里单独一个 `smoke` 任务跑。发布：`.github/workflows/pages.yml` + `tools/publish-pages.mjs`，每次推送 `dev` 先过 `npm run check`，再把产物推到 `gh-pages` 分支。详细步骤、要看什么、怎么反馈见 [playtest.md](playtest.md)。
- 3.5 为手机试玩做的两处 Web 改动：`platform/web.ts` 读真实的安全区（`env(safe-area-inset-*)`），不然 iPhone 上行李牌会被刘海盖住；`entry/web.ts` 在宽度变化（转屏）时刷新页面，高度变化（地址栏收起）不刷新。安全区在真机上才能验证，自动测试测不到。
- 3.5 玩法门禁已过：用户在手机上试玩前 10 关，结论是好玩，进入阶段 4。试玩中提出的具体问题没有记录（用户只给了"好玩"的结论）；手感参数（吸附半径、抬高、动画时长）和前 10 关的难度梯度仍按 backlog 里的记录，以后有反馈再调。
