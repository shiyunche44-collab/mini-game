# 路线图

分阶段的任务和进度。下一个任务就是表里第一个没打 ✅ 的任务。工作方式见 [CLAUDE.md](../CLAUDE.md#工作方式)。

每做完一个任务，在同一次提交里把它标成 ✅。阶段结束后由用户决定是否合并到 `main`。

## 阶段 0：先搭护栏（这个阶段不写任何游戏功能）

| 编号 | 任务 | 验收标准 | 状态 |
|---|---|---|---|
| 0.1 | 工程初始化：`package.json`、依赖、分层 tsconfig、`.gitignore`；把草稿移到 `drafts/` | `npm install` 成功，`npm run typecheck` 通过 | ✅ |
| 0.2 | 接口定义：`platform/types.ts`（Platform 接口、Canvas2D 子集接口）+ `test/fake-platform.ts` | 类型检查通过；假平台的自测通过 | ✅ |
| 0.3 | `check-arch.mjs`（含自测）+ `npm run check` 总入口 | 在 core 里临时写 `window` 或引用 game，检查会报错并指出规则；撤掉后通过 | ✅ |
| 0.4 | 文档：`docs/architecture.md`、ADR 0001～0003、`CLAUDE.md`、`docs/backlog.md`，以及 `docs/design.md`、本文件 | 用户通读一遍，确认规则 | ✅ |
| 0.5 | CI：GitHub Actions 跑 `npm run check` | 推送后 Actions 显示通过（如果没有权限推送 workflow 文件，说明原因，先只在本地检查） | ✅ |

## 阶段 1：核心逻辑（只有逻辑，没有画面）

| 编号 | 任务 | 验收标准 | 状态 |
|---|---|---|---|
| 1.1 | `rng`、`items` 迁移成 TS + 单测（旋转去重、emoji 位置） | `npm run check` 通过 | ✅ |
| 1.2 | 关卡生成器 + 单测：前 200 关都正好铺满；同一关号结果一致；每关生成小于 50ms | 同上 | ✅ |
| 1.3 | `npm run levels:preview`：在命令行打印前 N 关的文字版网格和物品清单 | 用户看前 10 关，判断难度梯度是否合理 | ✅ |
| 1.4 | 一局规则 `game.ts` + 单测：放置、移除、旋转、提示、快照与恢复 | `npm run check` 通过 | ✅ |
| 1.5 | 存档模型 `progress.ts` + 单测：读写、版本迁移、插屏频控；删除 `drafts/` | 同上 | |

备注：

- 1.1：草稿里的 `weightedOrder` 用了 `Math.pow`，已按 ADR 0003 换成逐个按权重抽取的写法（分布相同）。`test/core-determinism.test.ts` 检查 core 里没有 `Math.pow`、`**`、`Math.random`、`Date` 这类写法。
- 1.2：已按 ADR 0003 加上前 200 关的指纹测试。生成器改动让某一关变样时，要同时加 `GENERATOR_VERSION`、更新指纹。单次搜索的步数预算从草稿的 4000 降到 300：草稿的最坏一关要 40～60ms，现在 2 万关里最慢约 17ms，每次尝试成功率在 80% 以上。
- 1.4：`Level` 新增 `rotate`（这关能不能旋转），一局的规则要用；不影响生成结果，指纹没变。提示按答案摆：已经摆对的不挪，形状相同的物品互换，先摆大件，用托盘里的物品，挡路的退回托盘；不能旋转的关卡里只用朝向本来就对的物品。`restore` 对存档逐项检查，要么整份恢复，要么不改动。"重来"保留朝向和提示次数。
- 1.5：存档里记下进行中的关卡是哪个 `GENERATOR_VERSION` 生成的，对不上就让这一关重新开始（ADR 0003）。

## 阶段 2：运行时 + 静态画面（Web）

| 编号 | 任务 | 验收标准 | 状态 |
|---|---|---|---|
| 2.1 | engine：主循环、补间、输入识别（点击 / 拖动）+ 单测 | `npm run check` 通过 | |
| 2.2 | Web 平台实现、Web 入口、`build:web` 和 `dev` 命令、包体检查；先只画背景 | 浏览器能打开，看到背景 | |
| 2.3 | 布局 + 静态绘制：箱子、托盘里的物品、按钮、行李牌 | 375×667、390×844、桌面三种尺寸的截图发给用户确认视觉 | |

备注：

- 2.1：Platform 接口现在没有"下一帧回调"和时钟，主循环和补间需要它们（engine 不能直接用 `requestAnimationFrame`）。开始前先写 ADR 扩展接口，并让假平台可以手动推进时间。
- 2.2：`src/entry/tsconfig.json` 只带 ES2020。`entry/web.ts` 引用 `platform/web.ts` 时，后者会按 entry 的配置再检查一遍，DOM 类型会报错。要给每个入口配上对应平台的类型库。
