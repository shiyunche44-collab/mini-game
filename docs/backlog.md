# Backlog

计划外的想法和已知问题都记在这里，不在当前任务里顺手做。每条写清来源。排进 [roadmap](roadmap.md) 以后，就从这里删掉。

## 已知问题

### wechat.ts、douyin.ts 能用浏览器 API 并通过类型检查

- 来源：0.4
- 现状：`platform` 目录整体带 DOM 和微信的类型库。微信、抖音的实现里写 `window`、`document` 也能编译，但小游戏运行时没有这些对象。
- 已有的保障：4.1 的验收会检查产物里没有浏览器接口。
- 可选的改法：写 `wechat.ts`、`douyin.ts` 之前，给它们单独配一份不带 DOM 的 tsconfig，提前到编译期拦截。

### Web 平台改窗口大小后要刷新页面

- 来源：2.2
- 现状：`createWebPlatform` 只在创建时读一次窗口大小。Platform 接口没有"尺寸变了"的通知，手机转屏、桌面拖窗口之后，画面会拉伸或留白。
- 手机上竖屏锁定的话问题不大；桌面调试要手动刷新。
- 3.5 已经做了最简单的一种：Web 入口在宽度变化时刷新页面（只看宽度，手机地址栏收起时高度变不刷新）。桌面上拖窗口宽度会刷新，对调试够用。要不刷新页面重新排版，就得加 `onResize`，先写 ADR。

## 想法

### 按钮按下没有视觉反馈，提示没有高亮

- 来源：3.4
- 现状：重来、提示、跳关三个按钮点下去没有任何按下的样子，要等动作发生才知道点中了。提示摆好的物品也只是飞过去，没有闪一下告诉玩家"就是这件"。
- 看广告期间（真实平台上广告是原生界面盖在画布上）画布没有任何变化，Web 上是 DOM 弹层。到真机验证（4.1、4.2）时再看需不需要在画布上也给个"加载中"的状态。

### 下一关没有转场动画

- 来源：3.3
- 现状：点"下一站"后新一关直接替换，箱子、托盘一下子换了样子，有点生硬。
- 可选的改法：登机牌收起、新箱子从旁边滑进来。放在阶段 5 打磨一起做，或者 3.5 试玩时看玩家有没有觉得突兀。

### 托盘偏空、托盘里的物品偏小

- 来源：2.3
- 现状：托盘里每件物品占一个正方形位置（边长是最长的一边），长条形的物品（法棍、雨伞）周围空出一大片。375×667 上最难的关卡，托盘格子只有 19px，大约是箱子格子的一半。
- 3.1 做拖动时再看：手指拿起物品时会放大到箱子里的大小，托盘里小一点可能不影响手感。如果试玩觉得托盘里的物品太小、不好点，可以改成按每件物品当前的外框摆放，旋转时重排。

### 一局规则里几处手感上的选择，等 3.2、3.4 试玩时再定

- 来源：1.4
- 箱子里原地旋转时，中心对不齐就按"不动、左、右、上、下、斜角"的顺序挪着试，第一个放得下的就用。位置会不会"跳"得出乎玩家意料，要上手才知道。
- "重来"让物品回到托盘，但朝向保持现状，不恢复成一开始的朝向。
- 提示总是先摆最大的一件。

### 1.3 预览里看到的两处难度问题，等 3.5 试玩时再定

- 来源：1.3
- 第 6 关一下子引入三样新东西：拉杆槽、玩偶（十字形）、牛仔裤（∩ 形）。第 5 关已经允许出最难一档的物品，只是碰巧一件都没抽到。新形状第一次出现在哪一关，现在全看随机。
- 1×2 的小件偏多：运动鞋、防晒霜、帽子是同一个形状，各算各的权重，合起来占了所有物品的 31%（第 8～2000 关）。第 7 关的 13 件里有 6 件是 1×2。小件好塞，关卡会偏简单、偏琐碎。
- 可选的改法：前几关指定这一关必须出现哪些新物品；降低 1×2 物品的权重。改了要按 ADR 0003 加 `GENERATOR_VERSION`、更新指纹。

### 生成器里"物品太少就重来"的规则从不触发

- 来源：1.2
- 现状：`tile` 里要求物品数不少于 ceil(可用格数 / 4.5)。试过 1～20000 关，这条规则一次都没触发，因为大件的权重本来就高。
- 1.3 看预览时如果觉得物品太少、关卡太简单，可以考虑调这个系数，或者调 `SIZE_WEIGHT`。改了就要按 ADR 0003 加 `GENERATOR_VERSION`、更新指纹。
