# 试玩说明（roadmap 3.5 的玩法门禁）

用户在手机上试玩前 10 关，好玩再进阶段 4（微信、抖音适配），不好玩先调玩法。

## 怎么发布的

每次推送到 `dev`，`.github/workflows/pages.yml` 会先跑 `npm run check`，通过后把 Web 版构建产物推到 `gh-pages` 分支。`tools/publish-pages.mjs` 做这件事：每次都是只有一次提交的新分支，`game.js` 带着版本参数（手机浏览器会缓存脚本），另有一个 `version.txt` 写着是哪一版。

## 第一次要做的设置（需要仓库管理员）

1. **看一下仓库的套餐和可见性。** 这个仓库现在是**私有**的。GitHub Pages 在私有仓库上需要付费套餐（Pro、Team、Enterprise），免费账号用不了；免费账号要么把仓库改成公开，要么升级。另外**发布出来的页面任何人拿到链接都能打开**，没有登录保护（Enterprise Cloud 才有访问控制）。页面里只有压缩过的游戏脚本，源码和文档还在私有仓库里。
2. 仓库 **Settings → Pages → Build and deployment**，Source 选 **Deploy from a branch**，Branch 选 **gh-pages**、目录选 **/ (root)**，保存。`gh-pages` 分支要等第一次发布跑完才有，所以先让 `dev` 有一次推送，等 Actions 里的 `pages` 工作流变绿，再来设。
3. 等一两分钟，用手机打开：**https://shiyunche44-collab.github.io/mini-game/**。打开 `/version.txt` 能看到现在是哪一版（提交的前 7 位和时间）。

想让我在云环境里也能打开这个链接来验证，需要在环境设置里把 `shiyunche44-collab.github.io` 加进允许的域名（Network access → Custom → Allowed domains）。不加也不影响试玩。

## 玩的时候

- 进度存在浏览器里，每一步都存，关掉再开接着玩。想从头玩：清掉这个网站的数据，或者用 `?level=1`（这种方式不读不写存档）。
- 网址参数（只有 Web 版有，调试用）：`?level=10` 直接玩第 10 关；`?level=10&hints=99` 把箱子摆满，直接看过关画面。
- 提示、跳关用的是**模拟广告**：弹出一个 3 秒倒计时的卡片，倒计时完才能领取，右上角 ✕ 随时可以提前关（关了就拿不到）。真广告以后才有。
- 手机转屏会自动刷新页面重新排版，进度不会丢。

## 试玩前 10 关，请留意这些

核心问题只有一个：**玩完一关，想不想玩下一关？**

下面是帮你回忆的，不用逐条回答：

1. **难度**：前 10 关的梯度对不对？有没有哪一关特别卡、或者一路都太简单？（预览里我已经看出两处，见 backlog：第 6 关一下子引入三样新东西；1×2 的小件偏多。）
2. **手感**：拿起来会不会太飘、吸附准不准（拖到边上松手它落在了你想的地方吗）、点按旋转有没有点不中。物品比手指高 0.7 格、吸附半径 0.8 格，这几个数是我凭感觉定的。
3. **托盘**：里面的物品够不够大、好不好点？最难的关卡里托盘格子只有箱子格子的一半。
4. **看得懂吗**：第 1、2、6 关的教学提示够不够？点了不能转的物品没有任何反应，会不会让人困惑？
5. **提示、跳关、重来**：流程顺不顺？看广告的等待感可以接受吗？
6. **过关的节奏**：合盖、盖章、登机牌一共约 1.6 秒，会不会太长？
7. **设备问题**：刘海或底部横条遮住东西了吗？卡不卡？哪个机型、哪个浏览器？

## 反馈怎么写

写**关卡号 + 看到了什么 + 机型**就够了，比如"第 7 关，托盘里的法棍太小点不中，iPhone 13 Safari"。

## 看完之后

- **好玩**：进阶段 4。
- **不好玩**：先调玩法，再试玩。改关卡生成的规则要先写 ADR（ADR 0003 的确定性约束），改动让某一关变样时要加 `GENERATOR_VERSION`、更新指纹，已经存了档的玩家那一关会重新开始。
